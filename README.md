# optimal-stopping-fbm

Оптимальная остановка дробного броуновского движения со сносом.
[Теоретическое изложение](docs/README.md) объясняет постановку и методы;
этот файл описывает запуск, настройки и сохранённые результаты.

## Как связаны расчёты и теория

Основной путь: **03 → 04 → 05**. Отдельная проверка аналитики: **03 + 04 → 06**.
Нумерация глав docs задаёт порядок изложения и не совпадает с номерами ноутбуков.

| Ноутбук | Что делает | Теоретические главы |
|---|---|---|
| [01 — fBm](notebooks/01-fbm.ipynb) | Показывает свойства и генерацию процесса | [01 — модель](docs/01-problem-setup.md) |
| [02 — Один узел](notebooks/02-single-node.ipynb) | Оценивает стратегию при заданных mu и H | [03 — метод](docs/03-method-signatures.md), [04 — оценивание](docs/04-numerics.md) |
| [03 — Сетка](notebooks/03-grid.ipynb) | Обучает и тестирует стратегии для каждой пары (mu,H) | [03 — метод](docs/03-method-signatures.md), [04 — оценивание](docs/04-numerics.md), [05 — интервалы](docs/05-confidence-intervals.md) |
| [04 — Подбор на синтетике](notebooks/04-estimation.ipynb) | Готовит границы разных alpha, выбирает окна и метод оценки H, фиксирует победителя | [02 — границы](docs/02-theory-boundaries.md), [06 — методология применения](docs/06-empirical.md) |
| [05 — Реальные данные](notebooks/05-backtest.ipynb) | Проверяет зафиксированный выбор на рынке и строит диагностики | [06 — методология применения](docs/06-empirical.md) |
| [06 — Теория и практика](notebooks/06-theory-vs-practice.ipynb) | Сравнивает сохранённые стоимости и границы с аналитикой при alpha=0.1 | [02 — аналитические случаи](docs/02-theory-boundaries.md#27-аналитические-случаи) |

Синтетические траектории в 03 нужны для обучения стратегий при известных
параметрах. Синтетические рыночные сценарии в 04 нужны для выбора процедуры,
в которой параметры оцениваются по прошлым наблюдениям. В основном режиме
05 параметры процедуры заново не подбираются. Ноутбук 06 не требует запуска 05.

## Подготовка окружения

Установите зависимости и используйте Python из окружения проекта:

```bash
uv sync
```

Для работы из исходников каталог `src` должен быть в `PYTHONPATH` или
доступен через установленное окружение проекта. Выберите это же окружение
ядром Jupyter. Сведения о модулях — в [src/README.md](src/README.md).

## 03: обучение и независимый тест

Для нового расчёта задайте `MODE="fresh"`, новый `RUN_ID`, сетки mu и H
и конфигурацию процесса. Параметры текущего примера:

| Параметр | Значение | Смысл |
|---|---:|---|
| `T` | 1 | Нормированный горизонт |
| `n_exercise` | 21 | Положительные даты решений; вместе с нулём 22 даты |
| `n_fine` | 21 | Интервалы сетки наблюдений |
| `M_train` | 20 000 | Обучающие траектории |
| `M_test` | 20 000 | Независимые тестовые траектории |
| `M_VALIDATION` | 10 000 | Выбор действия в нуле до теста |
| `BATCH_SIZE` | 2 000 | Размер пакета теста |
| `COLLECT_PAIRED` | True | Собирать разности с удержанием на тех же траекториях |

`n_fine` должно делиться на `n_exercise`. Число интервалов и число дат
не следует смешивать. Повторный запуск с тем же идентификатором и совместимой
конфигурацией продолжает расчёт; готовые узлы пропускаются.

Результаты находятся в `result_optimal_stopping/runs/<RUN_ID>/`:
`experiment.json` и `config.json` описывают запуск, `policies/` содержит
стратегии, `states/` — моменты и checkpoints, `nodes/` — оценки узлов.
Сохранённые тестовые оценки исходных прогонов могут отражать прежний способ
выбора действия в нуле; их независимая проверка должна фиксировать это
действие до нового теста, не выбирать его по новым наградам.

### Старые прогоны без парной статистики

В конце 03 есть необязательная ячейка. Выполните импорты, задайте
`PAIRED_RUN_ID`, `RECOMPUTE_PAIRED=True` и при необходимости `PAIRED_H_VALUES`.
Запуск основного обучения выше не нужен. После пересчёта верните флаг в False.

Пересчёт воспроизводит исходный тест сохранённых стратегий, не переобучает их
и может быть длительным. Состояния сохраняются в `paired_evaluation/states/`;
готовые узлы пропускаются при продолжении. Исходные награды сверяются
с повторными. При наличии парных моментов в исходных `states/` они имеют
приоритет перед отдельной выгрузкой. Частичный пересчёт не заменяет полную
парную статистику для всех H.

## 04: границы и выбор настроек на синтетике

Укажите `RUN_ID` завершённого банка стратегий с парной статистикой и новый
`TUNING_ID`. Границы всех рассматриваемых alpha рассчитываются автоматически;
отдельный аналитический ноутбук для этого не нужен.

В текущем примере поиска заданы:

```text
H_windows     = (252, 504, 1008)
drift_windows = (21, 63, 126, 252)
sigma_windows = (63, 126, 252)
methods       = (rs, dfa)
alphas        = (0.05, 0.10, 0.20, 0.30, 0.50)

coarse / validation / test: 16 / 64 / 128 реплик
validation: top_k = 30
TUNING_ID = separate_windows_validation64_v2
```

Поиск перебирает декартово произведение трёх списков окон, метода и alpha.
Победитель выбирается на validation, фиксируется до независимого test
и не заменяется после просмотра test. Alpha=0.1 в аналитическом сравнении 06
не ограничивает сетку кандидатов подбора 04.

Каталог `result_optimal_stopping/synthetic_tuning/<TUNING_ID>/` содержит
настройки, границы `boundaries_alpha*.csv`, результаты этапов, checkpoints,
`frozen.json`, `frozen_boundaries.csv` и `test_complete.json` после завершения.
`final_boundaries.png` показывает границы выбранного alpha. `execution_audit.csv`
проверяет полноту сохранённых расчётов; `last_execution.json` описывает
последний запуск. Чтение готового кэша может быть быстрым и не означает
повторного обучения или повторной статистической проверки.

При изменении алгоритма, банка, настроек или окружения используйте новый
идентификатор, если проверка совместимости отвергает прежний. Не правьте
сохранённые контрольные суммы и не выдавайте старые результаты за новый расчёт.

## 05: проверка на реальных данных

Укажите `TUNING_ID` завершённого подбора. Загружаются зафиксированные окна,
метод H, alpha, границы и исходный банк стратегий. Основной режим не позволяет
заново выбирать эти параметры по рыночному результату.

- `REFRESH_DATA=False` использует локальный кэш котировок, если он доступен.
- `PLOTS_ONLY=False` выполняет полный бэктест и диагностику.
- `PLOTS_ONLY=True` читает готовые таблицы и перестраивает графики без нового бэктеста.
- `N_BOOT` и `BOOTSTRAP_EVERY` управляют бутстреп-диагностикой параметров.
- `RUN_RESEARCH=False` отключает дополнительный рыночный перебор; его результаты
  при включении не заменяют зафиксированную конфигурацию.

Результаты находятся в
`result_optimal_stopping/empirical/frozen/<TUNING_ID>/`.
`blocks.csv` содержит исходную хронологию бэктеста. Графики стоимости,
просадок, параметров, режимов и границ строятся из этих результатов.
В CSV лог-награды хранятся в долях; подписи графиков могут показывать проценты
лог-награды, которые не следует путать с простой доходностью.

Для отдельного анализа результата по H используются `H_DISTANCE_EDGES`,
`H_SIDE_THRESHOLD`, `H_CONTRAST_WIDTHS` и параметры `H_DIAGNOSTIC_*`.
Они определяют группы и бутстреп-интервалы, а не торговые решения.
Таблицы и графики находятся в `hurst_diagnostics/`. Интервалы разведочные,
не учитывают автоматически неопределённость самого оценённого H.

## 06: сравнение с аналитикой

Укажите согласованные `RUN_ID` и `TUNING_ID`. Ноутбук читает оценки стоимости
из 03 и таблицы границ, подготовленные в 04. Сейчас рассматривается только
`ALPHAS=(0.1,)`. Обучение и новая симуляция не запускаются.

Формула H=1 вычисляется для N из конфигурации исходного банка. Столбцы
Excel руководителя проверяются отдельно при наличии локального `mu_info`;
вычисленное значение для N из конфига не является готовым столбцом Excel.
Чёрные звёзды на графике границ — вычисленные по формуле epsilon-границы H=1
при alpha=0.1, а не точные границы без допуска. Сравнение с H<1 показывает
согласованность с предельной моделью, но не измеряет отдельно ошибку алгоритма.

`SAVE_ARTIFACTS=False` оставляет результаты в выводах ноутбука. При True
таблицы и графики дополнительно записываются в `analysis/theory_comparison/`
внутри каталога выбранного запуска.

## Дополнительный анализ сохранённой статистики

Отдельный прежний ноутбук анализа сетки удалён. Библиотечные функции доступны:
`load_experiment_statistics` читает моменты, `analyze_relative_run` строит
границы и диагностики без обучения. У него `gain_mode="paired"` задаёт парное
сравнение справа; `gain_mode="legacy"` вычитает теоретическое среднее удержания.
Левая оценка использует награды стратегии в обоих режимах.

Выгрузки сохраняются в `analysis/relative_paired/alpha_.../confidence_.../`
или `analysis/relative/alpha_.../confidence_.../`. Основные файлы:
`boundaries.csv`, `diagnostics.csv`, `sensitivity.csv`, `metadata.json` и графики.
`INCLUDE_UNCONFIRMED` в прежнем интерфейсе анализа соответствует
`include_unconfirmed` функции: это разрешение включать однозначные переходы
без ограниченного интервала в подгонку, а не дополнительная гарантия точности.

`raw` — исходная оценка перехода; `fit` — после ограничений формы.
`fitted_unconfirmed` означает отсутствие подтверждённой ограниченной локализации.
Пропуски, несколько переходов и переходы за краем сетки требуют диагностики.
В графиках пустые маркеры и пунктир отмечают менее надёжные оценки;
интерполяция отмечается отдельно и не создаёт новых доверительных интервалов.

`Boundaries.from_analysis` читает самостоятельные аналитические выгрузки
для совместимости. Основной рыночный путь использует `load_frozen_selection`
из завершённого подбора. Прежние форматы и исследовательские выгрузки
не следует смешивать с новым зафиксированным выбором.
