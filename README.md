# optimal-stopping-fbm

Оптимальная остановка fractional Brownian motion со сносом.
[Постановка и теория](docs/README.md) · [Практическая методика](docs/06-empirical.md).

Ноутбуки выполняются в следующем порядке:

1. [01 — fBm](notebooks/01-fbm.ipynb): свойства и генерация процесса.
2. [02 — Один узел](notebooks/02-single-node.ipynb): оценка стратегии при заданных μ и H.
3. [03 — Сетка](notebooks/03-grid.ipynb): обучение и независимый тест стратегий
   для каждой пары (μ, H). Задайте `RUN_ID`; повторный запуск продолжает расчёт.
   `COLLECT_PAIRED=True` сохраняет парные разности с удержанием для расчёта границ.
   Результаты — `result_optimal_stopping/runs/<RUN_ID>/`.
4. [04 — Подбор на синтетике](notebooks/04-estimation.ipynb): укажите банк `RUN_ID`
   и новый `TUNING_ID`. Границы для разных α готовятся из статистики 03.
   Подбор трёх раздельных окон, метода H и α выполняется только на синтетике:
   coarse → validation → фиксация → независимый test.
   Результаты — `result_optimal_stopping/synthetic_tuning/<TUNING_ID>/`.
5. [05 — Реальные данные](notebooks/05-backtest.ipynb): укажите тот же `TUNING_ID`.
   Загружается зафиксированная конфигурация, выполняются рыночный бэктест и
   диагностика параметров без нового выбора окон. Результаты —
   `result_optimal_stopping/empirical/frozen/<TUNING_ID>/`.
   Дополнительные исследования включаются отдельно через `RUN_RESEARCH=True`.
6. [06 — Теория и практика](notebooks/06-theory-vs-practice.ipynb): сравнение
   стоимости из 03 и границ из 04 с аналитическими эталонами H=1/2 и H=1,
   проверка Excel руководителя, влияние сетки. Только α=0.1, без нового обучения.
   Этот анализ не требует выполнения рыночного бэктеста 05.

Основной путь: **03 → 04 → 05**. Ноутбук **06** — отдельная проверка теории.

Для практической части нужен завершённый прогон с `n_exercise=21`
(21 положительная дата плюс ноль), например `daily21_21_train20k_test20k_v1`,
и парной статистикой. Для старых прогонов без неё в конце 03 есть необязательная
ячейка пересчёта: выполните импорты и эту ячейку, не запуская обучение.
Новые прогоны с `COLLECT_PAIRED=True` уже содержат нужные моменты.

Установка зависимостей: `uv sync`.
В 04 задан усиленный профиль: 16/64/128 реплик для coarse/validation/test,
`top_k=30`, `TUNING_ID="separate_windows_validation64_v2"`.
При изменении алгоритма или настроек используйте новый идентификатор;
результаты прежних экспериментов сохраняются.

Практические ε-границы определены на всей оси μ. Их разность может быть
отрицательной: это перекрытие областей близости стоимости к двум опорным
стратегиям. Эти оценки пока не подтверждены dual; выбор в нулевой момент
использует существующую поправку по тестовому среднему в исходном скане.
Независимая проверка фиксирует это старое решение до нового теста.
[Как считаются доверительные интервалы](docs/05-confidence-intervals.md).

Автоматические тесты в установленном окружении проекта:

```bash
python -m unittest discover -s tests -v
```
