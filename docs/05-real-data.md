# 5. Переход к реальным данным (S&P 500)

[← 04 численные эксперименты](04-numerics.md) · [оглавление](README.md) · далее: [06 — сравнение и метрики](06-evaluation.md)

---

## 5.1. Принцип walk-forward

Для каждого будущего торгового месяца используется **только** информация из прошлого:

```text
<------ estimation window ------>|<--- test month --->
        оцениваем a, σ, H         |  принимаем решения
```

Это исключает look-ahead bias: параметры месяца никогда не оцениваются по данным самого месяца.

---

## 5.2. Преобразование цен

Исходная модель $S_t = S_0 e^{a t + \sigma B^H_t}$ переходит в log-price:

$$
\boxed{\;Y_t = \ln\frac{S_t}{S_0} = a t + \sigma B^H_t.\;}
$$

На историческом окне нужно оценить $\hat a$, $\hat\sigma$, $\hat H$.

---

## 5.3. Оценка параметров (a, sigma, H)

Отдельный практический блок работы. Кандидаты:

- Gaussian Maximum Likelihood (по полной ковариационной матрице fBm);
- Whittle estimator (спектральный, устойчив и быстр);
- variance/time-scale estimators (aggregated variance, R/S);
- wavelet-based estimators для $H$.

**Обязательный предварительный шаг** — проверка оценщика на синтетике, где истина известна:

```text
известные a, σ, H  →  генерация synthetic fBm  →  оценка â, σ̂, Ĥ  →  сравнение
```

Это показывает не «работает ли метод в принципе», а **насколько велика дисперсия оценки при том размере окна, который реально доступен**.

> **➕ Дополнение: разные окна для разных параметров.** Это самое слабое звено эмпирической части, и его стоит признать явно. При $n$ дневных наблюдениях оценка $H$ и $\sigma$ сходится относительно быстро, тогда как drift $a$ на коротком окне оценивается крайне плохо: при окне длины $n$ отношение сигнал/шум у сноса растёт как $\sqrt{n}$ и не улучшается от увеличения частоты наблюдений. Между тем именно $\hat\mu=\hat a/\hat\sigma$ определяет режим. Практические выводы:
> 1. на синтетике измерить не только смещение, но и **стандартное отклонение** $\hat\mu$ при $n=60,125,250,500$ дней;
> 2. рассмотреть **разные окна**: длинное для $H,\sigma$, отдельное (возможно другой длины) для $a$;
> 3. переносить неопределённость дальше: определять режим не по точечному $\hat\mu$, а по доверительному интервалу — если он накрывает границу $\mu_1(\hat H)$ или $\mu_2(\hat H)$, режим считается неопределённым, и это честный результат, а не проблема.

## 5.4. ➕ Дополнение: единицы времени и пересчёт в месячный масштаб

В исходном плане нормировка выглядела как «поделить $Y_t$ на $\hat\sigma$». Этого недостаточно: параметры оцениваются на **дневной** шкале, а задача остановки поставлена на горизонте «месяц $=1$», и из-за самоподобия fBm масштаб времени входит нелинейно — через $H$.

Пусть $t$ измеряется в днях, окно даёт $\hat a$ (снос в день) и $\hat\sigma$ (в дневных единицах), а месяц содержит $N=20$ дней. Переходя к месячному времени $u = t/N \in[0,1]$ и используя $B^H_{Nu}\overset{d}{=}N^{H}B^H_u$:

$$
Y_{Nu} = \hat a N u + \hat\sigma N^{H} B^H_u ,
$$

то есть параметры **месячной** модели ($a_{\mathrm{month}}$, $\sigma_{\mathrm{month}}$):

$$
\boxed{\;
a_{\mathrm{month}} = \hat a\,N,
\qquad
\sigma_{\mathrm{month}} = \hat\sigma\,N^{\hat H},
\qquad
\hat\mu = \frac{a_{\mathrm{month}}}{\sigma_{\mathrm{month}}} = \frac{\hat a}{\hat\sigma}\,N^{\,1-\hat H}.
\;}
$$

Множитель $N^{1-\hat H}$ забывать нельзя: при $N=20$ и $\hat H=0.55$ он равен $\approx 3.9$, то есть игнорирование пересчёта меняет $\hat\mu$ в разы и может отправить месяц не в тот режим. Тот же множитель — частный случай закона скейлинга из [02.6](02-theory-boundaries.md#26--дополнение-скейлинг-по-горизонту).

Эквивалентная формулировка: сравнивать «дневное» $\hat a/\hat\sigma$ можно напрямую с пересчитанными границами $N^{\hat H-1}\mu_i(\hat H)$. Важно выбрать один из двух вариантов и последовательно его придерживаться.

## 5.5. Нормировка наблюдаемого пути

С учётом 5.4 нормированный путь для наблюдаемого месяца:

$$
\boxed{\;
\tilde X_u = \frac{\ln(S_{Nu}/S_0)}{\hat\sigma N^{\hat H}}
\;\approx\;
\hat\mu\, u + B^{\hat H}_u ,
\qquad u\in[0,1].
\;}
$$

Реальные данные приведены ровно к той форме, в которой решалась синтетическая задача: $X_u = \mu u + B^H_u$. Это и есть точка стыковки теории с практикой.

---

## 5.6. Теоретический прогноз режима для месяца

Имея кривые $\mu_1(H),\mu_2(H)$ из [04](04-numerics.md) и оценки $(\hat\mu,\hat H)$ для месяца, сравниваем:

| Условие | Прогноз теории |
|---|---|
| $\hat\mu \le \mu_1(\hat H)$ | не покупать / STOP сразу |
| $\mu_1(\hat H) < \hat\mu < \mu_2(\hat H)$ | нетривиальный optimal timing |
| $\hat\mu \ge \mu_2(\hat H)$ | купить и держать до конца |

Это **бесплатный прогноз**: он получается из двух чисел, без всякого обучения модели на месяце. Отдельный интересный результат работы — распределение реальных месяцев S&P 500 по этим трём режимам: если почти все месяцы попадают в режим HOLD, это само по себе содержательный вывод о рынке.

---

## 5.7. Построение практической stopping model

Для оценённой пары $(\hat\mu,\hat H)$ генерируются MC-траектории $X^{(i)}_u = \hat\mu u + B^{\hat H,(i)}_u$, на них считаются signatures и обучается backward stopping model:

```text
synthetic trajectories → Signatures → Continuation Value → STOP/CONTINUE policy
```

Два варианта организации вычислений:

1. **Переобучение каждый месяц** — точнее по параметрам, дороже по времени.
2. **Библиотека policies на сетке $(\mu,H)$**, заранее посчитанная в синтетической части; для месяца берётся ближайший узел (или интерполяция). Вычислительно удобнее и естественно переиспользует результаты [04](04-numerics.md).

Второй вариант предпочтителен: он же даёт бесплатную проверку чувствительности — насколько меняется решение при переходе к соседнему узлу сетки.

---

## 5.8. Применение к следующему реальному месяцу

В начале месяца наблюдается $S_0$; далее последовательно появляются $S_1, S_2,\dots$. На каждый день:

$$
\tilde X_{u_k} = \frac{\ln(S_k/S_0)}{\hat\sigma N^{\hat H}}
\;\longrightarrow\;
\operatorname{Sig}^{\le K}\bigl(\tilde X_{[0,u_k]}\bigr)
\;\longrightarrow\;
\hat C_{u_k}
\;\longrightarrow\;
\text{STOP / CONTINUE}.
$$

Первый день, когда модель говорит STOP, и есть практический момент продажи $\tau^*$. Если STOP не наступил ни разу — продажа в последний день месяца, то есть стратегия совпала с Buy-and-Hold.

> **➕ Замечание о честности бэктеста.** На тестовом месяце используются только: (а) цены до текущего дня включительно, (б) параметры и коэффициенты policy, полученные до начала месяца. В частности, $S_0$ и $\hat\sigma$ фиксируются на старте месяца и внутри месяца не пересчитываются. Полезно вынести этот инвариант в код отдельной проверкой.

## 5.9. Walk-forward backtest

Процесс повторяется для большого числа месяцев:

```text
история → параметры → январь  → τ*
история → параметры → февраль → τ*
история → параметры → март    → τ*
...
```

Для каждого нового месяца параметры $\hat a_t,\hat\sigma_t,\hat H_t$ оцениваются заново по окну, заканчивающемуся до начала месяца. Результат — out-of-sample траектория решений без использования будущей информации.
