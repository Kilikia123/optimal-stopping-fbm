# Карта исходного кода

Основной код расположен прямо в `src`. Старого пространства имён `osfbm` нет.
Импортируйте компоненты по их назначению, например:

```python
from config import Config
from estimation import EstimationWindows, estimate
from experiments.training import run_experiment
from tuning.frozen import load_frozen_selection
from visualization.boundaries import plot_final_boundaries
```

## Оценивание параметров — `estimation`

Это отдельный блок: он оценивает параметры процесса по прошлым дневным ценам.

| Модуль | Назначение |
|---|---|
| `types` | `EstimationWindows` и `ParamEstimate`: окна и результат оценки |
| `preprocessing` | Лог-доходности, удаление тренда |
| `hurst` | R/S и DFA, диапазон поддерживаемых H |
| `drift` | Средний дневной снос и пересчёт на D дней |
| `volatility` | Дневное стандартное отклонение и масштаб σ с учётом H |
| `pipeline` | Совместная оценка H, a, σ, μ и скользящие окна |
| `simulation` | Траектории для проверки оценивания и параметрического бутстрепа |
| `uncertainty` | Бутстреп оценок и процентильные интервалы |

`a` — снос, `α` — допуск при выборе границ: это разные параметры.
Оценивание использует отдельные окна H, a и σ. Время модели измеряется месяцами
из D торговых дней: `a = D × mean(r)`, `σ = std(r) × D**H`, `μ = a / σ`.

## Обучение и эксперименты — `experiments`

- `configuration`: проверка конфигурации, независимые seed, манифест эксперимента.
- `training`: обратная Ridge-регрессия, начальное решение, тестирование и продолжение.
- `policy`: применение и сериализация сохранённой политики.
- `policy_bank`: выбор ближайшего обученного узла и загрузка его модели/стоимости.
- `moments`: накопление статистики и Student-интервалы.
- `statistics`: чтение готовых узлов и статистики без обучения или симуляций.
- `paired`: парные награды на общих траекториях и проверка повторного оценивания.
- `audit`: независимая проверка фиксированных политик.
- `legacy_grid`, `checks`: прежний расчёт сетки и аналитические проверки.

## Границы — `boundary_analysis`

- `fixed`: сканирование и границы с фиксированным ε.
- `relative`: локализация границ при относительном допуске α.
- `inversion`: обращение полос наград в интервалы локализации границ.
- `monotone`: монотонная подгонка с аналитическим якорем H = 0,5.
- `curves`: таблицы μ₁/μ₂, интерполяция и выбор области cash/policy/hold.
- `preparation`: подготовка полных таблиц для синтетического подбора.
- `reporting`: экспорт анализа относительных границ и графиков чувствительности.

## Подбор на синтетике — `tuning`

- `config`: объявленная сетка кандидатов и размеры этапов.
- `scenarios`: сценарии рынков и независимые seed.
- `cache`: переиспользование оценок параметров и решений модели.
- `scoring`: равные веса групп, оценки качества, интервалы по независимым репликам.
- `runner`: coarse → validation → фиксация победителя → независимый test.
- `frozen`: фиксация, проверенная загрузка и применение выбранных настроек.
- `progress`: индикатор выполнения и аудит полноты.

## Реальные данные и анализ — `market`

- `data`: котировки, локальный кэш, даты и блоки.
- `backtest`: решения полной стратегии «границы + модель» и награды на блоках.
- `metrics`: доходность, риск, просадка и калибровка.
- `statistics`: HAC и парный блочный бутстреп.
- `validation`: соответствие сохранённых результатов выбранной конфигурации.
- `hurst_diagnostics`: результат полной стратегии по группам оценённого H.

`action_audit` — архивная диагностика дополнительных действий; в текущем 07
не используется. Рефакторинг не возвращает её в рабочий анализ.

## Графики — `visualization`

Модули `boundaries`, `relative`, `confidence`, `tuning`, `market`, `hurst` и
`style` отвечают за представление результатов. График окончательных границ
использует сохранённые поточечные интервалы; недостающие интервалы не достраивает.
Модуль `actions` относится только к архивной диагностике.

## Инфраструктура и сторонний код

`infrastructure.storage` выполняет атомарные записи, `identity` формирует
идентификаторы и версии зависимостей, `paths` задаёт пути независимо от текущей
директории. `provenance` проверяет вычислительную реализацию.

`verified_refactor.json` содержит точное соответствие проверенных контрольных
сумм до и после переноса. Только зарегистрированная новая сумма получает прежнюю
идентичность; дальнейшее изменение вычислительного кода создаёт новую сумму.
Изменения конфигурации, библиотек, политик и артефактов проверяются отдельно.
Не обновляйте этот реестр автоматически при изменении алгоритмов.

`vendor` — отдельный пакет исходного стороннего кода. Его файлы при переносе
сохранены побайтно. `adapter.py` содержит адаптацию вычислительного ядра,
`config.py` — общую конфигурацию, `core.py` — оценку отдельного узла.

## Как связаны ноутбуки

| Ноутбук | Основной путь выполнения |
|---|---|
| 01–02 | `adapter`, `core`, `experiments.checks`, `experiments.legacy_grid` |
| 03 | `experiments.configuration` → `training` → `statistics` |
| 04 | `experiments.statistics` → `boundary_analysis` → `visualization` |
| 06 | `tuning.runner` → `tuning.frozen` → `visualization` |
| 07 | `tuning.frozen` → `estimation` → `market.backtest` → анализ и графики |

Работа из исходников требует `src` в `sys.path` / `PYTHONPATH`. Текущая editable
среда уже включает эту папку. Настройка сборки установочного пакета в
`pyproject.toml` намеренно не менялась и пока относится к прежней структуре.
